# Annotation briefs and session notes

These four files are **committed copies** of documents the tools generate into
`data/gold/` next to the annotation sheets themselves. That directory is
gitignored because the sheets beside them carry the post text verbatim, so the
briefs are kept here instead — they are the instructions of record, and they
are worth reading before the code.

| File | Generated by | What it is |
|---|---|---|
| [`ANNOTATING.md`](ANNOTATING.md) | `pilot.py` | The order of work, the four reliability figures and what each one is worth, and how to fill a sheet. |
| [`annotator-b-brief.md`](annotator-b-brief.md) | `pilot.py --second-annotator` | The brief handed to the second annotator. The independence rules are the substance: different row order, no asking what a borderline case "should" be, every unasked question written down. |
| [`calibration.md`](calibration.md) | `calibrate.py` | How to run the 66-minute session that resolved the disagreements, and why the `rule_needed` column is the point of it. |
| [`pass1-notes.md`](pass1-notes.md) | `pilot.py` | The cover note on the first blind pass: what not to open, and why. |

Regenerating any of them overwrites the copy in `data/gold/`, not the copy
here. If the templates in `pilot.py` or `calibrate.py` change, copy the result
back over these files so the two do not drift.

`RUBRIC.md`, in the repository root, is the document all four of these point
at. It is the one an annotator actually works from.
