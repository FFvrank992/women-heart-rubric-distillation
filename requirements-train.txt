# --- Notes for anyone re-creating this ---
#
# bitsandbytes is the piece that breaks on Windows: a CPU-only wheel imports
# cleanly and then fails at the first 4-bit forward pass. smoke_train.py checks
# the kernels rather than the import for exactly that reason. If a future wheel
# is CPU-only, WSL2 is the fallback.
#
# triton is absent, so torch prints a flop-counter warning at import. Harmless
# here: it only affects flop counting and torch.compile, neither of which this
# pipeline uses. Unsloth would need triton-windows.
#
# Set PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True before importing torch
# (smoke_train.py does). At 8 GB the allocator otherwise fragments and OOMs well
# below the real limit.
#
# Disable the NVIDIA driver's CUDA system-memory fallback. With it on, exceeding
# VRAM silently spills to host RAM and training gets ~20x slower instead of
# raising OutOfMemoryError, which is much harder to diagnose.
